Prompt 接口契约速查

一个可测试 Prompt 需要明确“做什么、凭什么做、不能做什么、怎样算完成”。

契约部分Prompt 中的问题前端类比
角色 / 目标模型负责完成什么任务？函数职责
输入会收到哪些业务信息？参数类型
约束哪些内容禁止猜测或越界？前置条件
输出格式结果必须有哪些区块？返回类型
验收标准怎样判断结果合格？测试断言
示例哪些难以言明的边界需要演示？测试样例 / Story

实验纪律

一次只改变 Prompt 版本，固定模型、参数、测试输入和评分规则。先写预期，再运行；不要看完输出后修改评分标准。

三个常见误区

  • 长 Prompt 不等于好 Prompt：重复规则会增加成本，也可能制造冲突。
  • few-shot 不保证更好：示例只有在编码产品要求或修复已测失败时才值得保留。
  • 文字相同不等于稳定：稳定应看关键验收项是否重复通过。
