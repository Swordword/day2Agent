需求澄清链路速查

完成闭卷题后再看。区分当前代码已经实现的能力，与完整 CLI 仍需补齐的能力。

数据与职责

用户文本
  → validate_requirement：拒绝空输入
  → build_structured_prompt：描述输出契约
  → call_model：获取模型文本
  → extract_json_block：提取候选 JSON
  → json.loads：解析 JSON 语法
  → Requirement.model_validate：验证字段与约束
  → RequirementResult：保存结果与尝试记录
  → 交互层：展示、收集补充信息、请求确认

request_requirement 组织模型调用、解析和结构化输出失败后的有界修复重试；它不负责终端输入，也不负责用户确认。

默认 max_attempts=3 表示最多调用模型三次，包含首次调用，因此最多再修复两次。格式校验成功就提前结束。

错误边界

现象当前代码中的处理
空白输入validate_requirement 抛出 ValueError；不应调用模型。
无 JSON 或 JSON 语法错误parse_requirement 转为 StructuredOutputError，request_requirement 用 repair prompt 有界重试。
合法 JSON，但缺少必填字段Pydantic 校验失败，转为 StructuredOutputError，再进入有界重试。
模型请求超时或网络错误当前 request_requirement 不捕获 call_model 抛出的异常；完整 CLI 的用户提示与网络重试尚未实现。
没有待确认问题仍需用户确认；decide_next_step 将其视为待确认草稿。

证据边界

单元测试通过，能证明被测试的纯函数与结构化输出流程在这些输入下符合预期；不能证明终端交互、真实模型网络调用、异常用户提示或陌生输入的端到端运行。

检查第 1 周交付时，分别记录“已通过”“未通过”“缺证据”。没有做过的运行，不写成成功。
