1. 闭卷检索（20 分钟）

先不看代码、笔记和速查表，回答以下四题。把答案发给我，我会逐题反馈。可先填入 W1D7 学习笔记。

  1. 从用户输入需求到最终确认，画出至少六个步骤，并标出一次可能的重试。
  2. validate_requirement、request_requirement、Requirement.model_validate 各负责什么？谁负责和终端交互？
  3. 模型返回合法 JSON，但缺少 tasks。这属于哪一类失败？应该由哪一层处理？
  4. open_questions 为空时，为什么仍不能直接将草稿标记为最终结果？

2. 对照代码与测试（25 分钟）

核对 W1D5 结构化输出流程、W1D6 纯函数。测试由助手维护和运行，以下命令供你理解和复现：

uv run pytest labs/w1d1 labs/w1d2 labs/w1d3 labs/w1d4 labs/w1d5 labs/w1d6 -q

助手于 2026-09-28 验证：57 项测试全部通过。用两句话说明：这些测试证明了什么？它们为什么还不能证明完整的终端 CLI 已经可运行？

答完第一节后，用 第一周链路速查 校对职责与错误边界。不要把当前未实现的模型超时处理写成已完成。

3. 失败情景复盘（25 分钟）

情景你的判断
输入只有空格在哪一层拒绝？是否调用模型？
模型请求超时谁记录错误？是否重试？
返回有效 JSON，但字段不满足 schema谁校验？何时修复？
草稿没有问题，但用户要求修改状态应如何变化？

4. 第一周交付复盘（40 分钟）

再写一段不超过 150 字的费曼解释：为什么需求澄清程序需要把交互层、业务状态层和模型适配层分开？
