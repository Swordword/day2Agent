0. W1D2 闭卷热身（10 分钟）

先填写 notes/W1D3.md 的两题，不看旧笔记。重点检索“并发/并行”和异常隔离原因。

1. 消息是带角色的输入（15 分钟）

system 放应用级规则，user 表达用户请求，assistant 保存模型先前输出，tool 把工具执行结果送回模型。角色会影响指令层级和一段内容在对话中的意义。

先填写四种角色的一句话解释，再阅读 Message 模型。注意：token_count 是实验中已测得的数据，不是字符数。

2. 先给输出留座位（15 分钟）

上下文容量同时容纳输入和输出。若容量为 100、预留输出为 20，则历史消息只能使用 80。预留不是本次实际输出用量，而是为可能生成的输出留下容量。

3. 实现最近历史裁剪（45 分钟）

完成 context_manager.py 的 TODO 1～3。策略固定为：保留全部 system 消息，然后从新到旧连续选择能放入预算的非 system 消息，最后恢复时间顺序。

这里采用简单策略学习边界；生产系统还可能按完整对话轮次、摘要、消息重要性或工具调用配对来裁剪。

在测试数据或临时脚本中依次改变：输入预算、system 长度、最新 user 长度、预留输出量，以及某条旧消息长度。每次先写预测，再运行并记录实际结果。
