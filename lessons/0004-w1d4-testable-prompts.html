把 Prompt 写成可测试的接口契约

今天你会把自然语言需求转换成前端任务，用同一批用例比较 zero-shot 与 few-shot。最终判断依据不是措辞是否漂亮，而是固定验收项是否通过。

今日可验证成果

  • 完成 zero-shot、few-shot 两版 Prompt
  • 7 项本地契约测试通过
  • 完成 10 条测试输入的盲评
  • 比较正确率、稳定通过率和 Token
  • 完成 150 字费曼卡片与每日评分

0. W1D3 闭卷热身（8 分钟）

先填写 notes/W1D4.md 的两题。它会复习 Token 算术，并暴露“单条裁剪可能拆散工具调用”的问题。

1. 先写契约，不先堆措辞（15 分钟）

在笔记中定义角色/目标、输入、硬约束、输出格式和验收标准。Prompt 的作用类似函数接口：它不能保证实现永远正确，但能让调用者和评测者知道什么结果算合格。

2. Zero-shot：不给示例（20 分钟）

完成 prompts.py 的 TODO 1。要求模型输出前端任务、验收标准和待确认问题；缺少后端契约或业务规则时不得自行补齐。

3. Few-shot：只加一个有目的的示例（20 分钟）

完成 TODO 2。示例必须纠正一个具体边界，例如“需求含糊时提出问题，而不是编造 API”。除示例外，两版契约尽量一致，才能做公平对照。

4. 自动反馈（10 分钟）

uv run pytest labs/w1d4/test_w1d4.py -q

这些测试只能证明 Prompt 包含必要契约，不能证明模型输出语义正确；后者由固定用例与评分表负责。

5. 十条用例与重复实验（35 分钟）

固定模型和参数，分别运行 10 条输入。先按 4 项规则盲评，再选 3 条输入，每版重复 3 次。稳定性看验收项的重复通过率，不要求文字完全相同。

uv run python -m labs.w1d4.run_experiment \
  --output labs/w1d4/results/all-cases.jsonl

uv run python -m labs.w1d4.run_experiment \
  --cases 2,5,10 --repeats 3 \
  --output labs/w1d4/results/repeated-cases.jsonl

第一条命令共调用 20 次，第二条共调用 18 次，会产生 API 用量。先完成 Prompt 和本地测试，再决定运行；可先用 --cases 1 做两次冒烟调用。

6. 费曼复述与评分（12 分钟）

完成笔记中的约 150 字卡片和复盘。全部完成后，我会检查代码、评测记录并按每日五维量表评分。
