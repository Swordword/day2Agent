## 5. 费曼卡片：《好 Prompt 为什么像接口契约》

请用约 150 字回答，必须包含：输入、输出、约束、验收标准，以及“示例不是越多越好”的原因。

好的 prompt 会指定用户的输入来自于哪里，任务是什么，输出的格式是什么，约束是指对当前任务添加自定义的限制，验收标准要设置为可观察
示例为什么不是越多越好：

示例以1-2 个为佳，示例过多的话，容易引起歧义，然后容易导致约束不住

优化的答案：

好的 Prompt 像接口契约：它先定义模型会收到什么输入、要完成什么目标，再规定输出格式、硬约束和验收标准。输入是用户需求，输出是可执行任务与可观察的验收条件；约束要求模型不编造 API、字段或业务规则，信息不足时提出问题。示例用于展示难以描述的边界，通常一两个就够，过多可能增加 Token、引入冲突或限制模型泛化。即使 Prompt 契约清晰，也必须通过测试验证结果。

  在模型调用时，为任务进行约束，约束的范围可能会不全

  失败的用例，可以在 prompt 中进行反馈修改，添加一个避免场景的模块
