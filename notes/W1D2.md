## dataclass 与 Pydantic

<!-- 它们分别适合什么数据？为什么模型外部输入更适合 Pydantic？ -->

1. dataclass 适合系统内部、可信稳定的数据结构，但是不会检查内省

   ```python
   from dataclasses import dataclass
   
   @dataclass
   class Price:
       amount: float
       currency: str
   
   def calculate_total(price: Price, count: int) -> float:
       return price.amount * count
   ```

2. Pydantic 适合外部对接的数据结构，返回数据不可信，会对数据结构的类型做校验

   ```python
   from pydantic import BaseModel, Field
   
   class CreateUserRequest(BaseModel):
       name: str = Field(min_length=1, max_length=50)
       age: int = Field(ge=0, le=150)
       email: str
   ```

3. 模型外部输入更适合 Pydantic：模型外部，即便要求它返回 JSON 数据结构，但是得到的结果也是不可信的，需要进行强制校验

### 概念：Semaphore

- 一句话解释：

  协程控制并行最多执行的任务

- 它解决的问题：

  控制同时执行的最大次数

- 输入、输出与状态：

  不知道

- 最小例子：

  ```python
  async with semaphore:
          started_at = perf_counter()
          try:
              async with asyncio.timeout(timeout):
                  await fake_model_call(name, delay)
                  status = "ok"
                  error = None
          except asyncio.TimeoutError:
              status = "timeout"
              error = None
          except Exception as e:
              status = "error"
              error = str(e)
          elapsed_ms = round((perf_counter() - started_at) * 1000)
      return CallResult(name, status, elapsed_ms, error)
  ```

  

- 它最容易失败的地方

  ~~超时，任务 down 住~~

  修正：常见风险是 忘记释放许可，导致后续任务一直等待

- 与前端概念的类比：

  ~~类似前端的 promise~~

  类似前端并发池或者 p-limit
