## 1. 结构化输出目标

- 为什么需要结构化输出？

  结构化输出可以明确数据结构，用于下个会话中方便序列化输入

- JSON Schema 和 Pydantic 模型的关系？

  JSON Schema 是 JSON 格式的文件，并不能在模型响应时约束数据结构，Pydantic 是 Python 的 class 类，在模型返回时，可以校验数据结构是否是 Python 程序预期的，不是的话，可以直接报错

- 格式失败和校验失败的区别？

  格式失败是校验出格式并不是我们想要的
  
  校验失败，对模型返回的结果进行校验时报错了，并不能确认返回的数据格式一定有误

请用约 150 字回答，必须包含：格式失败、校验失败、repair prompt 的作用，以及为什么不能无限重试。

**你的答案：**

格式失败：llm 返回的数据并不一定是一个有效的 json 数据

校验失败：llm 返回的是个 json，但是 json 中的字段并不是类型定义的指定字段

repair prompt：如果遇到格式失败或者校验失败，则根据之前的上下文生成一个 修复的 prompt，重新调用 模型

为什么不能无限重试：无限重试有可能导致模型调用死循环

## 8. 今日复盘

- 最容易遗漏的校验规则：

  需要重点复习：格式解析和结构校验是两步；嵌套列表的最小长度约束；拒绝未知字段；`open_questions` 的默认值；重试次数必须有明确上限。

  标注：这是本周需要间隔复习的重点模块。尤其要记住：合法 JSON 不等于符合业务结构。

- JSON Schema 自动生成的好处：

  在 `labs/w1d5/prompts.py` 的 `response_schema_text()` 中，
  `Requirement.model_json_schema()` 根据 Pydantic 模型自动生成 JSON Schema，
  再序列化成 Prompt 文本。这样模型提示和程序校验共用同一份模型定义，字段变更时不容易出现两边不一致。

- 可迁移到求职作品或个人产品的场景：

  求职作品中的“需求澄清助手”可以让模型输出固定的任务、验收标准和待确认问题，
  后端用 Pydantic 校验，失败时通过 repair prompt 重试。个人产品中的简历优化器也可以用同样方式输出固定的经历、技能匹配点和缺失信息，方便前端渲染和后续流程继续处理。
